# main 与学习版本怎样一起演进

main 保持最新、已经验证的实现，Git 提交历史保留每轮演进。每个主要学习阶段只保留一个分支：目前是 milestone/v1 和 milestone/v2。

| 引用 | 职责 | 更新方式 |
|---|---|---|
| main | 最新可运行实现、教程与路线图 | 每个通过检查的小迭代都合入并推送 |
| milestone/vN | 该阶段的学习实现 | 可纳入同阶段的使用优化；不混入下一阶段能力 |
| vN / step-* 标签 | 精确的历史验收与章节快照 | 创建后不移动 |
| codex/* | 正在进行的改动 | 完成、验证、合入目标分支后清理 |

## 提交与整理

从 main 开始一个可解释的改动，运行相关检查，提交后 fast-forward 或正常合并回 main，再推送。保留教学步骤，不通过 squash 压掉有学习意义的提交。为旧阶段回移使用优化时，在对应学习分支验证并推送；不要把较早 backend 合并覆盖 main。

长期保留 main、milestone/v1、milestone/v2，以及现有历史标签。后续版本沿用一个阶段一个学习分支的规则，不为同阶段的交互改进另开版本入口。

清理临时分支前先刷新远端引用，确认其提交已在 main 或发布的学习分支中。处理工作树中的未提交文件后再移除临时工作树。删除旧名称不删除已保留的提交；清理后核对章节标签、代码基线和历史验收仍可访问。
