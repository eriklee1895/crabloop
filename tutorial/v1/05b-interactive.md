# 接着问下一句

上一节里，CrabLoop 已经能够完成一次修复。我们请它检查文件、修改代码、运行测试，最后得到一个回答。可是一旦想接着说“把刚才那个文件再改一下”，程序已经退出了。重新启动时，那份只存在于内存里的历史也消失了。

现在先从使用方式改起。直接运行 `cargo run`，应该出现一个可以输入任务的终端界面。想在脚本里执行一次任务时，再写 `cargo run -- -p "检查 README"`。两种入口背后仍然使用同一条模型—工具循环。

这是后续交互专题，当前 milestone/v1 已回到单任务核心。为单独观察交互增量，本章使用历史提交 `9c5cb11`，其中不含 v2 的压缩。`step-05-v1` 和历史 v1/v2 标签保持原样；main 已把交互接到 v2 上。可以从该历史提交创建练习分支，查看全部改动：

```bash
git switch -c my-chat-exercise 9c5cb11
git diff step-05-v1..9c5cb11 -- src Cargo.toml
cargo run
```

这份 diff 包含完整导入、入口和依赖变更。源码在根目录 src/，不是另一份例子。加入配置读取、输入编辑、取消和展示后，完整代码会超过最初的约 300 行；原始小循环仍可通过 v1 单独学习，交互版按全部 src 如实计数。

## 历史应该由谁持有

先打开 src/lib.rs。原来的 `run(config)` 在函数内部创建 `input`，结束时一起丢弃。我们把这些需要跨提问保留的东西放进一个具体的 `Session`：配置、HTTP client、工具声明和消息历史。一次用户提问调用一次 `Session::turn`；其中仍然可能发生多次模型请求和工具执行。

入口的关键关系可以缩写成下面这样。它是阅读导航，完整实现与错误处理在 src/lib.rs 和 src/terminal.rs：

```rust
let mut session = Session::new(config)?;
session.turn("创建一个文件", progress).await?;
session.turn("修改刚才那个文件", progress).await?;
```

`&mut self` 在这里很具体：这一轮会修改同一份历史，因此下一轮必须等它结束。HTTP client 和工具定义可以复用。界面只负责取得下一句话，再把它交给这个状态持有者。

尤其要检查最终回答的处理位置。如果一看到 Final 就 return，尚未保存的最终回答会从下一次请求中消失。正确顺序是保存完整 response output，连同相应工具结果保留，再结束这一轮。第二次用户提问发送时，输入的顺序应该是：第一次提问、模型行动与工具反馈、第一次最终回答、第二次提问。

打开 tests/conversation.rs，运行：

```bash
cargo test --locked --test conversation
```

这里检查的是实际发送到本地 HTTP fixture 的请求。模型是否准确记住某件事，是另一个需要真实任务观察的问题；消息确实被传入，则能用确定性断言检查。

## 一层薄薄的终端界面

src/cli.rs 把启动分为两种模式：终端里不提供任务就聊天，`-p` 提供单次任务。当前目录作为工作目录，因此平常只需 `cargo run`。src/main.rs 根据模式进入聊天或调用原来的 `run` 包装函数。

src/terminal.rs 用 rustyline 处理输入编辑和方向键历史。每次 readline 后，它识别 `/new`、`/exit` 这些本地命令，其余文字交给 Session。Session 延迟到第一条真正的任务才创建，所以打开界面又退出，不会产生模型请求。

模型等待与工具执行也需要让人看见。loop 在开始一次模型请求、开始工具、结束工具时，调用 `Progress` 回调。交互界面显示短消息；单次入口继续输出适合查看的工具 JSON。工具执行仍然在 loop 里，界面没有另一套调用规则。

当前模型回答是整段返回的。我们先把连续对话的状态关系接好，后面再研究文字增量和完整屏幕布局。

## 亲手观察一次连续修改

准备好当前目录的 `.env` 后，直接启动。可以输入下面两句话；这是练习任务，模型措辞和工具顺序可能不同：

```text
创建 hello.txt，内容为 Hello, CrabLoop!，然后读回来。
把刚才文件里的 Hello 改成 Bonjour，再读回来。
```

第二句话没有重复文件名。程序需要把上一轮对话一并发送，让模型找到“刚才文件”的指代。完成后在另一个终端运行 `cat hello.txt`，检查实际文件。仓库的 [真实录制与验证](../../evidence/interactive/README.md) 就使用了这两个相关任务的英文版本。

接着输入 `/new`。它清空模型会话，已经写到磁盘的文件仍在。最后输入 `/exit`；再次启动时没有跨进程历史，这部分属于后面的 sessions 章节。

如果执行中按 Ctrl-C，工具可能已经改变了文件。程序会停下当前回合，要求检查文件后用 `/new`，避免在不完整历史上盲目继续。取消不等于回滚，当前 Bash 实现也没有进程树清理保证。

完成这一步后，CrabLoop 便能接住下一句话了。历史因此也更容易变长；当你开始想知道“哪些旧内容还需要发送”，就可以继续读 v2 的[上下文投影](../v2/06-context-projection.md)。
