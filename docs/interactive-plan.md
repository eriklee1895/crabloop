# 提前加入可用的交互入口

用户已明确要求基本多轮终端交互属于早期版本，`-p` 用于一次性任务，并在 README 展示真实运行。本次按该要求实施，不再把基础聊天延后到 v6。

- 默认启动进入轻量滚动终端界面：输入编辑、历史按键、模型/工具进度、`/new`、`/exit`。使用 rustyline，不引入完整屏幕布局框架。
- `-p/--print TASK` 执行一次并退出；保留原有任务参数和管道兼容方式。`--chat` 可显式进入聊天模式，便于终端外验证。
- 一个 Session 持有 client、对话历史与 journal，多个用户回合复用。`run(Config)` 保留为单次调用包装。
- v2 的当前用户任务保持独立锚点，旧问题与最终回答按原顺序进入历史；压缩不删除当前问题或拆开调用/结果。
- 模型/协议/记录错误或中断后阻止继续使用可能不完整的历史，提示 `/new` 与核对文件；工具错误仍正常反馈。不要自动重试副作用。
- 原 v1/v2 标签不移动。交互增量统一纳入 `milestone/v1` 学习分支，保留四工具和完整内存历史，不带 v2 压缩。完整行数按实际统计。
- README GIF 从真实 PTY 输入输出生成，用 DeepSeek 完成两轮关联任务，外部检查文件结果；保留脱敏录制与复现说明。

实施顺序：会话与 CLI 契约测试 → 同一 loop 的状态持有者 → 终端输入/展示 → 真实运行录制 → v1 学习分支 → 文档、检查、提交并更新 main。

重点检查：最终回答进入下一轮；新用户问题位置正确；压缩后最新问题保留；`-p` 不混入交互提示；退出空会话不调用模型；中断未知结果不重放；GIF 与实际代码/任务结果一致。

验证完成：61 Rust 与 6 Python 测试、fmt/clippy、真实 DeepSeek 两轮任务、独立文件/历史检查、PTY Ctrl-C 与 /new 检查。README GIF 已渲染并检查关键帧。v1 交互实现为 571/581 行，43 Rust 与 3 Python 测试通过；主线为 813/825 行。最终代码审查未发现阻塞问题。
