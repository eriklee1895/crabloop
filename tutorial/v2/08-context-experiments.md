# 08：更短的输入，保住了哪些事实

摘要请求能成功返回以后，很容易只盯着 bytes 下降。先留住这个冲动，拿同一段历史做三次选择，看看每次究竟少了什么。

## 把三个方案放在同一份记录上

tests/fixtures/context/history.json 有四组完整交互。早期记录故意标出 INITIAL_TEST=failed、POST_EDIT_TEST=not_run、REPAIR=pending，后两组只包含最近读到的文件。我们使用这些明确标记，让保留与丢失成为能确定检查的事实。

在仓库根目录运行：

```bash
cargo test --locked --test context context_comparison -- --nocapture
```

当前实现下的实测结果是：

| 输入选择 | 完整请求 bytes | 调用/结果成组 | 三个预设事实 |
|---|---:|---|---|
| 全部历史 | 6989 | 保留 | 保留 |
| 最近两组 | 1577 | 保留 | 丢失 |
| 正确摘要 + 最近两组 | 1851 | 保留 | 保留 |

原任务和固定指令在三个方案里都保留。第三种方案使用人工 fixture 摘要；它证明输入组织可以做到什么，不代表真实模型一定能写出同样准确的摘要。[机器记录](../../evidence/v2/context-comparison.json) 给它标明了这个身份。

接着运行 `cargo test --locked --test compaction misleading_summary`。这次摘要把失败与未运行都写成通过，栏目齐全，大小合格。prepare 会接受它，但独立事实核验失败。这个测试没有发明一个能自动判断任意中文摘要真假的判官；它只核对我们事先植入的三项事实，用来暴露“结构合格”与“内容可信”的距离。

## 让真实模型遇到小预算

真实实验继续用 last_index 修复。工作区根目录 AGENTS.md 要求保留签名和测试、先测再改再测；任务只要求一份简短 NOTES.md，完成后结束。

```bash
python3 scripts/run-live.py --stage v2 --provider deepseek \
  --context-bytes 10240 --require-compaction
```

本次运行使用 deepseek-flash，11 个主轮中成功整理 5 次，最终正常结束；原测试没有变化，独立 4 项测试通过，任务与 AGENTS 在全部主请求中保留。压缩前后分别为 8408→7346、8497→6046、9071→5993、8972→5808、7703→6253 字节。实际结果见[运行记录](../../evidence/v2/20261011T143500013361Z-coding-deepseek.json)。

这条命令是复现实验的方法，不保证每次恰好压缩五次。模型可能合并工具调用或更快完成；require-compaction 检查本次是否真正覆盖了压缩路径，和修复是否通过分开记录。

## 失败让预算的含义更具体

8 KB 曾在只有两组历史时达到整理阈值，无较早前缀可移走，程序明确停止。16 KB 的一次短任务直接修复成功，没触发摘要；它不能算压缩验收。

另外几次总结因为 max_output_tokens 不足而 incomplete。默认思考会消耗生成额度；摘要正文很短，也不意味着整个生成过程只需那么多 tokens。最终方案为摘要保留至少 4096 tokens，并使用 reasoning.effort=none；主任务保持模型默认思考。DeepSeek 与 GPT-6 Luna 支持这个参数，换其他模型时需要复核，不能由“支持 Responses”推断所有 effort 都可用。

还有一次运行成功整理了九次，源码已修好，却因反复验证旧结果而用完可用输入。我们补充了完成条件：过去真实观察到的成功测试，经过摘要以后仍然是已完成证据；不能仅因记录变旧就创造新的待办。最终摘要大小限制没有放宽，工具或副作用也没有自动重试。

## 成功任务里仍可能有错误表述

逐份读成功记录的摘要，可以追踪测试状态：早期未运行，随后基线失败，修改之后未重测，最后三项测试实测通过。签名与 tests.rs 的约束、待写的 NOTES 也保留了。

但首份摘要同时说“读取了 AGENTS.md”和“AGENTS.md 内容未读取”，还把用户任务中“约五行”的要求归到 README。它保留了主要行动事实，却在来源与读取状态上有矛盾。真实任务通过并不能抹去这些偏差。

这就是接下来使用摘要时应有的习惯：保留原记录，把摘要当成可核查的索引；涉及当前文件和重要结论时，再按需要查证。测试通过来自实际结果，不来自摘要写得像一个可信的故事。
