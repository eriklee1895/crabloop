# v1 的教学边界

更新：2026-10-14。v1 保持小而可读的教学目标；用户已取消行数硬门禁，替代此前严格少于 400 行的要求。

v1 要让用户与其他 agent 学习者快速看完核心实现，建立第一份可追踪的心智模型：请求模型 → 识别工具调用 → 执行工具 → 关联结果并回传 → 继续或停止。复杂 Harness 从后续迭代逐步生长。

## 规模与取舍

- 目标约 300 行，行数用于提醒范围和阅读成本，不作为验收门禁。需要了解规模时，可以运行 `python3 scripts/count-lines.py` 查看统计。
- 保持公开 rustfmt 风格。测试、文档、fixture 与开发脚本另计；运行逻辑不可移出 src 藏起来，也不可藏进框架、压缩格式或删除必要错误处理。
- 根据教学需要控制功能范围。基础启动便利可以保留；成熟编辑器、终端布局、provider 自动选择等放在后续阶段，避免扩大 v1 的学习负担。
- v1 保留手写循环、四工具、完整响应、明确停止和必要的输出/请求限制。工具失败能带原 call_id 回传；模型结束与独立任务验证保持区分。
- v2 专注上下文管理与压缩，继续非流式；基础 SSE 放入 v3 的独立增量。更丰富的 TUI、配置/目录、Skills、恢复与 memory 分阶段加入。

## 教学完成标准

学习者应能从入口顺着代码解释：谁维护历史，模型何时决定调用工具，谁真正执行，失败如何成为下一次输入，以及程序为何结束。能亲手运行一次真实的工具反馈闭环，并修改一个工具验证自己的理解。

单次用户任务中的多轮模型—工具交互已经能展示 agent loop。用户连续聊天属于另外一层交互能力，其规模和教学成本需要单独取舍。清晰的状态和控制流需要人工审视，不能靠行数判断。
